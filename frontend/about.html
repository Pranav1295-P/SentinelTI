Every Sample Begins as Evidence

Start with a file.
SentinelTI turns its bytes into a verdict you can explain.

Static analysis · five agents · one evidence graph

SentinelTI reads a file without ever running it. It identifies what the file really is, extracts structured evidence from its headers, sections, imports and strings, and correlates that evidence into capabilities that can be proven.

Each finding is mapped to MITRE ATT&CK, checked once more, and published as an interactive attack graph and a PDF report. The sections below explain each step.

1.1

Start witha Sample

An investigation usually starts with one suspicious file: an attachment, a dropped binary, something a user downloaded. Deciding whether it is dangerous — and why — is the first job.

SentinelTI does that first pass for you and records how it reached its answer. You still own the decision, with the evidence in front of you.

1.2

How SentinelReads a File

Magic bytes reveal the real type, whatever the extension claims. Cryptographic hashes fingerprint it. Strings, PE headers, section tables and import tables expose what the code is built to do — and packers or high entropy show what it is trying to hide.

Every technique used by a manual analyst — HxD, PeStudio, FLOSS, Dependency Walker, YARA, Ghidra — becomes a tool an agent can call.

2.1

How an AgentThinks

Every agent follows the same loop. The model chooses a tool from the task and the evidence so far; the call is validated with Pydantic; the quarantined sample is loaded and a parser runs. Only the parser's structured output moves forward.

LLM / Triage AgentChooses an available tool from the task and evidence
Tool CallingValidates input with Pydantic, loads the quarantined sample, invokes a parser
Structured EvidenceTyped facts handed to the next agent
